# Publishing and outreach checklist

## Public release readiness

- [ ] Review source license and ownership (MIT is included as a proposed permissive license).
- [ ] Read `SECURITY_PRIVACY.md`, especially Zotero local write authorization.
- [ ] Make sure there are **no personal SQLite catalogs, secret API keys, private DOCX manuscripts or unredacted logs**.
- [ ] Run `python -m unittest -v` and save the output.
- [ ] Review/record the exact Windows/Word/Zotero versions used for a fresh external demo.
- [ ] Create a **public** GitHub repository named `zotero-autocite` with **no autogenerated README/license** (provided here).
- [ ] Upload/push the files from this package, maintaining directory structure.
- [ ] Confirm GitHub Actions CI is green.
- [ ] Replace `[INSERT THE PUBLIC GITHUB REPOSITORY URL]` in `FORUM_POST.md`.
- [ ] Add a real 60–90 second demonstration video, if available.
- [ ] Post the reviewed forum draft; avoid opening an upstream GitHub issue/PR without maintainers' guidance.

## Creating the GitHub repo manually

1. Sign into the GitHub account that should own the project.
2. Visit https://github.com/new, select the owner, enter `zotero-autocite`, choose **Public**, and **leave README, .gitignore and license options blank**.
3. Click **Create repository**. Copy the resulting `https://github.com/OWNER/zotero-autocite` URL.
4. You may upload the prepared files from your computer, or return to ChatGPT with the new empty repository link so the connected GitHub app can commit this project there.

If using the Git CLI locally after repository creation, open a terminal in the extracted project directory:

```bash
git init -b main
git add .
git commit -m "Initial public beta: AutoCite 0.5"
git remote add origin https://github.com/OWNER/zotero-autocite.git
git push -u origin main
```

Replace `OWNER` with your actual GitHub account/organization; you must have Git and authentication configured. Do **not** publish the local `%APPDATA%\ZoteroAutoCite` folder.
